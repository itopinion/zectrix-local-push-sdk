面向普通开发者的 PC 控制入口

Zectrix 局域网发现与
UDP 显示音频协议

PC 显式连接后接管显示和音频路由。图片使用 zlib 压缩的黑白、四灰或十六灰像素，声音使用 Opus 流；远程模式下确认键长按触发采集、松开停止，其余单键动作通过 KEY 事件交给 PC，PC 保活维持管理权。设备长按退出后，必须由 PC 重新发起连接。

01范围与基本约定

为局域网中的桌面程序和 SDK 提供直接控制设备的入口。设备提供 UDP 服务，无需连接 PC 服务器；同一时刻只有一个管理 PC。

功能约定
发现mDNS 按需查询，也可指定 IP
管理PC 连接后接管业务显示、扬声器及麦克风数据去向
图片400×300、1/2/4bpp、zlib 压缩；完整校验后显示
音频Opus、16 kHz、单声道、60 ms；统一实时流
采集远程模式下确认键长按达到 1000 ms 才开始，松开停止；数据只发给管理 PC
按键事件确认键短按、上／下键短按与长按通过 KEY 上报 PC；正常模式使用独立的原有处理
失联PC 每 5 秒保活，设备 15 秒未收到新保活则退出管理
本地退出同时长按上、下键 3 秒；PC 必须显式重新连接

SDK 负责图片转换与压缩、音频文件转码、收发与重试，用户只操作连接、显示、播放和输入订阅。订阅麦克风不主动开启录音；每次有效的确认键长按产生独立语音段，确认键短按只产生 KEY 事件。

本版固定当前设备格式，不做账号鉴权、加密、通用任务平台、多客户端排队、文件存储、多种编解码协商或全双工。PC 可播放文件，但 SDK 将其转成实时 Opus 流；丢包时允许补偿，不承诺逐帧无损送达。

远程期间暂停云端语音、普通提示音、轮播及自动跳页对音频和显示的竞争；后台数据同步可继续。系统关机、恢复出厂和本地退出始终优先。系统事件的优先级不表示远程按键可以落入正常模式的关机、恢复出厂或其他业务回调。

02发现、连接与退出

发现

发布 _zectrix._udp.local.，默认业务端口 32342，以 SRV 记录为准。TXT 仅放稳定设备 ID、型号和协议主版本，不放电量或播放状态。

联网时正常探测名称并公告，稳定运行时以监听响应为主，不额外周期报在线。SDK 只在用户发现设备或地址失效时浏览，缓存地址后使用单播。默认发现窗口 5 秒，允许延长；查不到不等于设备已关机。

一个连接编号即可

设备启动时生成非零随机 64 位 connection_id。空闲时它是本次连接可使用的编号，接管成功后继续作为当前会话编号；退出、接管失败或重启后更换。它用于隔离旧数据，不是鉴权凭据。稳定设备 ID 仅用于发现和确认设备身份，不放进每个数据包。

用户点连接SDK 准备接收端点
→
INFO取得当前连接编号
→
CONNECT绑定 PC，显示管理提示
→
PALETTE读取设备色板
→
连接成功PC 开始保活
  1. SDK 查询 INFO，确认设备身份、当前状态及连接编号。
  2. 显式发送 CONNECT，带该编号和 PC 显示名称。设备忙碌、正在退出或退出键未释放时直接拒绝，不排队。
  3. 设备收尾本地音频，绑定请求源 IP、端口，暂停业务显示竞争，显示远程管理提示；完成后回复成功；SDK 随后查询 PALETTE，读取并校验色板后才报告已连接。
  4. PC 持续保活；图片、播放及每段采集均使用同一管理连接。

CONNECT 重传保持原编号、序号和内容；准备中不重复执行，成功后可重发原响应。其他 PC 不能抢占。连接准备失败或超时后更换编号，本次请求失效。模式切换时取消旧模式的待判定动作和计时，所有按键稳定释放后才接受新模式的新按压；过渡期间保留设备端组合退出入口，不补发普通 KEY，也不启动语音。

退出不能触发自动接管

  1. 设备长按退出、PC CLOSE、保活超时或网络丢失时，立即撤销所有者并更换连接编号。
  2. 停止旧音频，取消未完成图片；物理刷新已开始则安全收尾，旧回调不能恢复远程状态。
  3. 恢复本地音频路由和页面，按需刷新退出提示。按键仍按住则等待释放，不把同一段改发云端。
  4. 尽力向旧 PC 发送 CLOSE 通知及原因，不等待确认才退出。UDP 与 mDNS 可继续监听。

SDK 进入“需要重新连接”，停止旧请求和保活。重新发现、网络恢复、重建端口均不能自动接管。只有用户或上层应用新的显式连接操作，才可查询新编号并发送新 CONNECT；不能在退出回调里自动换编号重连。

设备对旧编号先判无效，再考虑重复响应缓存，因此旧 CONNECT、旧成功响应、旧保活均不能复活会话。编号变化后，同一次连接操作不得自动查询新编号重试。连接编号挡住旧包，SDK 的显式连接规则挡住自动生成的新申请。

03报文与消息

所有业务消息使用二进制；多字节整数采用网络字节序。每个 UDP 数据报只放一个消息，负载含公共头不超过 1200 字节，UDP 校验和开启。

公共字段字节含义
magic2固定 ASCII 字节 ZL
version1固定为 1
type1消息类型；最高位为响应标记
connection_id8当前连接编号；INFO 请求为 0
sequence4请求关联或数据序号，按类型解释

公共头共 16 字节。长度从 UDP 数据报取得；不重复传启动标识、请求 ID、头长、负载长和保留字段。图片和音频的数据包额外带 4 字节传输／流 ID。

类型值消息必要负载与作用
1INFO请求无负载；响应给出设备身份、管理状态、固定显示与提示区信息，响应头带当前连接编号
2CONNECT1 字节名称长度及最多 48 字节 UTF-8 PC 名称
3PING无负载；仅维护当前管理权
4CLOSE1 字节原因；PC 主动释放，或设备通知已退出
5IMAGE_BEGINu8 bpp（1=黑白、2=四灰、4=十六灰）+ u16 压缩长度；本消息序号即图片 ID
6IMAGE_DATA图片 ID 4 字节 + 最多 1024 字节数据；头部序号为块号
7IMAGE_STATUS图片 ID 4 字节；响应返回接收／刷新／完成状态和 64 位接收位图
8AUDIO_BEGIN1 字节音量，0～100；设备上行为 0 并忽略。本消息序号即流 ID
9AUDIO_DATA流 ID 4 字节 + 一个 Opus 包；头部序号为帧号
10AUDIO_END流 ID 4 字节、总帧数 4 字节、末帧有效采样数 2 字节、结束原因 1 字节
11AUDIO_STOP流 ID 4 字节；提前终止指定流，不开启新采集
12STATE查询当前管理、图片和音频状态，以及最近各一项图片／播放结果
13RESULT原开始序号 4 字节、对象类型 1 字节、结果 1 字节；通知显示或播放完成／失败
14KEY2 字节：key（上=1、下=2、确认=3）与 action（短按=1、长按=2）；仅远程模式向管理 PC 上报
15STATUS请求无负载；查询电量百分比、充电状态与 Wi-Fi RSSI。仅当前远程管理 PC 可查询，使用只读查询序号。
16PALETTE请求无负载；成功响应为结果码 + 四灰 4 个亮度字节 + 十六灰 16 个亮度字节，共 21 字节。只读查询，不改变显示。

除 DATA 两类外，响应均为原 type 设置最高位，回显 sequence 和 connection_id；INFO 响应的编号例外，返回设备当前值。负载首先放 1 字节结果码，再放该查询所需数据。PING 成功响应只需该结果码，不另传时间戳、代次或任务状态。响应本身不再要求确认。

INFO 与 STATE 是只读操作，不取得管理权。其他请求和媒体均校验连接编号、所有者端点及当前状态。退出后的 CLOSE 确认可作为有限收尾处理，不恢复旧会话。畸形长度、非本协议包直接丢弃。

KEY 使用现有设备事件序号、响应和重试规则，PC 回复类型 0x8E 并回显连接编号与序号。重复 KEY 仍需确认，但 SDK 对用户只回调一次；退出后停止旧 KEY 重试，不向新连接补发。无需新增事件 ID、按压时长或时间戳。

v1 固件固定响应布局

以下字段按列出的顺序连续编码，无对齐填充。u8、u16、u32、u64 分别为 1、2、4、8 字节无符号整数；多字节整数均为网络序。所有响应先放 u8 结果码；失败响应只有结果码，不附查询数据。

响应成功结果码之后的字段
INFOu8 管理状态；u8 设备 ID 长度及对应 ASCII 字节；u8 型号长度及对应 UTF-8 字节；u16 宽、u16 高、u16 提示区 x、y、宽、高。当前 ID 为小写无分隔符的 12 位 Wi-Fi MAC，型号为 zectrix-s3-epaper-4.2，尺寸为 400、300、0、0、0、0。
IMAGE_STATUSu8 图片状态；u64 接收位图。图片 ID 从请求取得。可查询最新提交、正在物理刷新或最近完成的图片；未知 ID 返回 INVALID。
STATEu8 管理状态、u8 图片状态、u8 音频状态；u32 图片 ID、u64 接收位图、u32 当前音频流 ID；u32 最近图片 ID、u8 图片结束原因；u32 最近播放 ID、u8 播放结束原因。不存在的对象 ID 为 0，其结束原因忽略。
PALETTE成功响应总负载 21 字节：u8 结果码 0；u8 gray4[4]；u8 gray16[16]。数组按灰号排列，亮度为归一化线性亮度，0=本屏黑端点、255=本屏白端点。
STATUS成功响应总负载 4 字节：u8 结果码 0、u8 电量（0～100，255=未知）、u8 充电（0=否、1=是、255=未知）、i8 Wi-Fi RSSI（-127～0 dBm，127=未知；有符号单字节二进制补码）。不附加其他状态字段。

管理状态：0 LOCAL、1 CONNECTING、2 REMOTE、3 EXITING。图片状态：0 无图片、1 RECEIVING、2 REFRESHING、3 DONE、4 FAILED。音频状态：0 空闲、1 播放准备、2 播放（含排空）、3 采集（含准备）、4 采集收尾。RESULT 对象类型：1 图片、2 播放。

CLOSE、AUDIO_END、RESULT 和 STATE 中的结束原因统一编码为：0 正常、1 设备主动退出、2 保活超时、3 网络变化、4 系统中断、5 按键打断、6 采集或时长超限、7 处理失败。RESULT 的结果字节使用该结束原因；0 才表示正常完成。普通控制响应仅带结果码，设备事件的确认也仅带结果码 0。

mDNS TXT 固定使用 id、model、version 三个键，version 为字符串 1。固件在接管期间临时保持 Wi-Fi 待机能力，不更改用户保存的待机设置；退出后恢复原设置。空闲监听及 PING 不申请常驻唤醒锁。

控制序号、PING 序号、只读查询序号和每条流的数据序号分别计数；各发送方向独立。控制从 1 开始递增，流帧与图片块从 0 开始。图片／流 ID 直接复用相应 BEGIN 的控制序号，不再分配任务 ID。控制或保活序号耗尽前结束连接，流序号耗尽前结束流，不在同一上下文内回绕。

STATUS 为兼容扩展，电量查询不修改 INFO 与媒体报文；图片的统一格式见第 05 节。请求须使用当前 connection_id、所有者端点、非零查询序号且处于远程模式；有效响应 type=0x8F。查询不推进控制序号、不延长保活、不触发采样或应用层唤醒。电量来自最近一次 ADC 采样缓存，待机不强制更新；Wi-Fi 只读取已关联 AP，不扫描。SDK 按需查询、约 5 秒超时，建议轮询间隔至少 30 秒。旧固件会忽略新类型而超时，其他接口仍可使用。

04确认、保活与错误

只保留三种可靠性处理

内容处理
控制、KEY、开始／结束和最终结果响应确认、同序号有限重传；相同请求不重复执行
图片数据64 位接收位图，缺哪块补哪块，不逐块确认
实时音频序号重排、丢包补偿、丢弃过期包，不逐帧确认或重传

PC 同一时间只等待一个普通状态修改命令的响应，图片数据与音频数据不受此限制。CLOSE、STOP 可以优先发送更高控制序号；旧的未执行命令随后被拒绝。PING 和只读查询不推进控制序号，不会使在途控制失效。

设备为 PC 的状态修改命令保留控制高水位及少量重复响应记录。重复包返回原结果；记录已覆盖的旧序号返回 OLD_REQUEST，绝不重新执行。同序号不同内容返回 INVALID。SDK 对设备事件按对象和序号去重，不因较新的 KEY 或 RESULT 先到而丢弃另一对象的有效事件，也不能把已经结束的流重新开启。

待机请求初始等待建议 1500 ms，超时退避，总请求期限 15 秒；连接准备最多 10 秒。未收到最终结果时可查询 STATE 或当前 IMAGE_STATUS，但不能换序号自动重新播放或刷图。STATE 只保留当前和最近结果，查不到就报告结果未知，不建立长期任务历史。

PC 保活

PC 在整个远程管理期间每 5 秒发送新 PING，包括没有录音、播放和图片更新时。设备进入 REMOTE 时启动首个 15 秒期限，此后仅在连接仍有效且序号更新时续期，15 秒无新 PING 退出。重复 PING 可重复回复，但不延长期限；重复 CONNECT 也不续期。

PC 15 秒没有收到匹配新 PING 的成功确认，也结束本次连接并等待显式重连。单次丢包不立即退出；音频包、普通命令和设备单方面持续上传不能代替保活。到期先退出，迟到 PING 不能复活连接。

设备只应答，不主动维持第二套心跳。确认和续期不刷新 UI、不打开音频、不持有持续唤醒锁。SDK 的连接对象负责保活，设备收到的是“PC 仍管理我”，而不是“某一段录音仍在继续”。

有限结果集

响应结果码固定为：0 OK、1 BUSY、2 INVALID、3 STALE、4 FAILED、5 OLD_REQUEST。STALE 表示连接无效，SDK 停止旧管理操作；OLD_REQUEST 只终止对应旧请求，不解除当前连接。忙碌不排队自动执行。具体结束原因放在 CLOSE、AUDIO_END 或 RESULT 中，限定为正常、设备主动退出、保活超时、网络变化、系统中断、按键打断、采集超限及处理失败。

确认等待不阻止浅睡眠，最终通知最多重传到 15 秒。设备本地退出立即生效，即使 CLOSE 通知丢失，PC 后续的旧请求也无效。

05zlib 图片传输

远端只声明图片位深，不指定刷新方式。IMAGE_BEGIN 的负载固定 3 字节：u8 bpp + u16 compressed_size；不含显示模式切换命令或 refresh 字段。远端完成缩放、灰阶量化与抖色，传完整 zlib 二进制；设备校验后根据位深和显示历史自动选择波形。

项目固定规则
原图400×300，逐行存储；bpp=1/2/4 对应每行 50/100/200 字节，总计 15000/30000/60000 字节
位序与颜色最高位像素在左；1bpp 为 0=白、1=黑；2bpp 为 0=黑…3=白；4bpp 为 0=黑…15=白（高半字节像素在前）
压缩完整 zlib 流，DEFLATE、无预设字典；SDK 默认压缩等级 6
长度上限压缩长度 1～65535 字节；解压必须恰好为 15000 × bpp 字节
分块每块 1024 字节，最后一块可较短，共 1～64 块
完整性UDP 校验和、zlib 自带 Adler-32 和输出长度检查，不叠加 MD5、SHA 或图片 CRC32

传完整画布，SDK 根据 INFO 返回的区域布局内容。当前固件开放完整 400×300 画布，INFO 的保留区域为 0、0、0、0；远程画面的顶部像素完整保留，没有固定标题栏或留白。首次连接且尚未收到画面时，设备使用自带字体显示默认远程页面。画面留白也参与 zlib 压缩，不另定义裁剪传输、差分图片或多种压缩格式。

远程期间的待办提醒以顶部通知覆盖层呈现，不退出远程模式、不切换本地页面。有声提醒同步播放设备提示音；若正在播放远程音频，以现有本地中断原因码 5 结束该播放，SDK 返回 Interrupted。提示音播放期间新的远程播放请求返回 Busy。录音中或确认键仍按住时延后提醒。通知约 12 秒后自动收起，或按确认键收起并停声；收起不会完成待办，待办重试规则保持不变。通知期间仍接收远程画面，收起后恢复最新画面；IMAGE 的成功结果表示刷新完成，通知可能仍覆盖其中一部分。

格式错误明确报错：IMAGE_BEGIN 长度不为 3、bpp 不为 1/2/4 或压缩长度为 0，返回 INVALID；分片编号或长度错误不接收，重复分片内容冲突使图片失败。zlib 校验失败、截断、尾随数据、输出长度不匹配均使 IMAGE_STATUS=FAILED，并通过 RESULT 返回失败。校验成功之前不修改显示模式、底图、旧图基准或维护计数。像素数据没有 PNG/JPEG 文件头；同长度但错误位序或极性的内容无法自动识别，须遵循打包规则。

设备根据图片位深和显示状态自动选择刷新方式，并在需要时清残影。首次显示或切换位深可能耗时较长；相同图片可能跳过刷新。远端不指定波形或维护参数。

设备色板 PALETTE（type=16 / 0x10）

请求使用当前 connection_id、非零只读查询 sequence，负载为空；响应 type=0x90，回显连接编号和序号。仅当前所有者可查询，接管准备/退出期间返回 BUSY，非空请求负载返回 INVALID，没有可用色板返回 FAILED；失败响应仅 1 字节结果码。其他端点不响应，旧连接返回 STALE。查询不推进控制序号、不延长保活、不采样硬件、不刷新屏幕。

设备在连接准备完成时固定本连接色板。SDK 在 CONNECT 成功后查询一次，严格校验 21 字节长度、首项为 0、末项为 255、各表非递减；允许重复亮度，不能按亮度重新排列灰号。SDK 读取超时、设备报错或色板非法时连接失败并发送 CLOSE 释放管理权，不回退到电脑端默认值。重新连接重新读取，不增加版本号或协商报文。

成功响应负载（偏移从 0 开始）：
0       result: u8 = 0
1..4    gray4:  u8[4]
5..20   gray16: u8[16]

色板值表示 0～255 的线性亮度，下标为显示灰号，以连接时查询结果为准，不能写死在应用中。同一位深的不同刷新方式共用色板。黑白使用固定端点，不额外传色板；图片仅声明 bpp。

SDK 将 PNG 视为 sRGB，解码到线性 RGB 后按 0.2126R+0.7152G+0.0722B 计算亮度，在该线性域合成白底、选择最近的设备色板亮度，并用“输入亮度－选中灰号的色板亮度”做 Floyd–Steinberg 误差扩散。相同距离或重复亮度取最小灰号。线性亮度用 0～255 表示，SDK 内部保持浮点精度；sRGB 128 约对应线性亮度 55，不能直接当作色板亮度 128。

一次显示流程

  1. SDK 使用连接时读取的设备色板完成图片缩放、抖动和压缩，发送 IMAGE_BEGIN，携带 bpp 和压缩长度。
  2. 设备允许一个物理刷新任务与一张后续图片缓存。屏幕 BUSY 期间可继续接收下一张图片；已有图片正在接收、后续缓存已满或正在录音时返回 BUSY。
  3. SDK 按受控节奏发送 IMAGE_DATA，建议初始块间隔 2 ms；不用逐块等待 ACK。
  4. 本批发送后查询 IMAGE_STATUS。接收位图的位 n 表示第 n 块已经收到；SDK 只补缺块。丢包增多时放慢发送，超时退避。
  5. 设备收齐后验证完整 zlib 流、校验值、输入消耗及解压长度；屏幕空闲时自动显示，屏幕忙时保留已校验图片，当前刷新结束后再取缓存显示；不需要额外 COMMIT。
  6. 设备发送 RESULT，区分已显示与失败。SDK 确认；通知丢失时查询 IMAGE_STATUS 或 STATE，不重建图片任务。

IMAGE_STATUS 状态为 RECEIVING、REFRESHING、DONE 或 FAILED；位图以网络序 64 位整数表示，最低位对应块 0。SDK 合并收到的位图，乱序响应不能把已确认块变成未收到。尾块长度必须与总长度一致，未使用位为 0。

接收 15 秒无进度或总计 30 秒未完成则失败并释放缓冲，重复块不计新进度。已收齐进入刷新的图片不再适用传输超时，按显示驱动的有限执行期限处理。REFRESHING 同时表示已校验等待屏幕空闲或正在物理刷新；查询与 RESULT 均按图片 ID 区分。设备仅保留一个后续缓存，不无限排队。SDK 可并发提交两次 show，串行传输、重叠接收和显示；更高频更新由调用方合并尚未提交的图片。物理刷新超过 30 秒则退出连接，丢弃后续缓存，避免在驱动仍忙时继续派发；SDK 对已收齐图片最多等待 60 秒（含排队）。

坏图和不完整图不刷新；最终合成画面相同且显示状态可信时可直接成功。退出管理先作废连接，已开始的物理刷新安全收尾后恢复本地页，旧显示完成回调不得重新进入远程管理。

06按键采集与音频播放

上下行共用 Opus、16 kHz、单声道、60 ms，每帧 960 个采样。方向由发送方确定；每包一帧，附带流 ID 和帧序号。格式不逐包重复，采样位置由帧序号乘 960 得出，无需单独时间戳。本版不做应用层静音删帧。

设备按键采集

  1. 确认键按下只开始远程模式的长短按判定，不开麦克风，也不打断 PC 播放。未满 1000 ms 就松开时，只上报确认键短按 KEY。
  2. 确认键连续按住达到 1000 ms，且仍处于同一次远程管理时，消费本次长按、创建语音流 ID 并固定接收 PC；若正在播放，此时才停止播放并废弃旧流。
  3. 准备录音时显示白底黑字、2px 圆角边框的顶部单行提示“正在聆听 / 松开结束”，复用本地语音输入的内置 beep.ogg 提示音，沿用当前音量。输入在提示音及 DMA 排空期间保持关闭；喇叭关闭且确认键仍按住后，才开始采集并发送 AUDIO_BEGIN 和 AUDIO_DATA。准备期间松开或退出会取消启动，不等待每段远程应用批准或开始通知确认。
  4. SDK 可根据当前连接和新流 ID 先接收先到的音频，再合并迟到的开始通知；缓冲有上限。
  5. 松开立即停止新采样，关闭输入，有限处理已经采集的尾部，发送 AUDIO_END。
  6. 远程应用确认结束，按有限尾包窗口完成本段。录音条收起后恢复最新远程画面，不播放结束音；新到期的待办通知延后到录音结束呈现。设备回到远程空闲，管理保活继续。

AUDIO_END 带总帧数及末帧有效采样数：有帧时为 1～960，无帧时两者均为 0。最后不足一帧的采样由编码端补齐，接收端按有效长度裁掉填充。开始与结束可重传，音频包不重传。

确认键短按不产生 AUDIO_BEGIN 或 AUDIO_END。达到长按阈值后，若准备完成前已经松开，则取消采集准备，可以返回零帧 AUDIO_END，但不得迟开麦克风，也不得再补发短按 KEY。确认键长按及其释放由音频流程消费，不额外上报 KEY 长按。PC 可用 AUDIO_STOP 中止当前采集，但不能命令开启新采集。连接失效、采集超限或被中止时，按键仍按住则等待释放；同一次按住不自动切到云端。

PC 播放

PC 发送 AUDIO_BEGIN 和音量，设备准备完成回复后开始按 60 ms 节奏发送数据。文件播放同样由 SDK 转码成这一种流，不先传整份文件。正在准备采集、采集或异常等待确认键释放时，播放申请返回 BUSY。确认键尚未达到长按阈值时不占用音频资源；其他 KEY 事件本身不打断播放。

发送完毕后 PC 发 AUDIO_END。设备接收有限尾包、播放剩余有效声音，关闭输出并发 RESULT；END 的响应只表示收到结束指令，不代表声音已经播完。AUDIO_STOP 则清空指定流并尽快停止。确认键长按打断后不自动续播，PC 要重新发起播放。

缓冲与旧包

初始播放缓冲 3 帧（180 ms），接收队列上限 6 帧（360 ms），发送端不突发灌入整段音频。迟到帧丢弃，丢失帧使用补偿；连续 3 秒无可用输入且没有有效结束信息则结束播放流。短于 3 帧的声音在 END 到达后按实际帧数播放，不无限等待启动缓冲。普通丢包不解除管理权。

每段使用新流 ID，旧流帧不能进入新流；新开始事件不能被旧结束事件覆盖。SDK 按方向记录当前和最近流即可，不保存长期语音任务。麦克风采集与 PC 播放半双工，确认键达到长按阈值后的采集优先。接收或播放异常时停止该流，管理仍由 PING 决定。

按键交互与待机

远程连接空闲时仍需按协议保活。按键按下后设备提高网络响应速度，松开后保持 3 秒，后续按键重新计时。PING、查询及普通后台推图不延长该时段；到期时已在处理的图片会先完成。SDK 收到 KEY 后可直接更新画面，无需额外设置。

刷新方式和清残影由设备决定，按键响应时段不保证首帧一定快刷。设备从待机恢复后的首帧可能耗时较长，应用应等待图片结果。
